Срез с шагом: начало и strides

SIMD сложение: четыре float64 за раз

Пример для x86 с 256-битными векторами AVX: 256 / 64 = 4 элемента.

ymm0 = [a[i], a[i+1], a[i+2], a[i+3]]
ymm1 = [b[i], b[i+1], b[i+2], b[i+3]]
ymm2 = [a[i]+b[i], ..., a[i+3]+b[i+3]]
; Схема в Intel-синтаксисе; rax — смещение в байтах
vmovupd ymm0, [rdi + rax]        ; загрузить 4 числа a
vmovupd ymm1, [rsi + rax]        ; загрузить 4 числа b
vaddpd  ymm2, ymm0, ymm1         ; 4 попарных сложения
vmovupd [rdx + rax], ymm2        ; записать 4 результата
add     rax, 32                  ; следующий блок
Это учебная схема, не дизассемблирование NumPy. Достаточно AVX; AVX2 также поддерживает эти инструкции. У AArch64 с NEON 128-битный вектор вмещает 2 float64.

Цикл, остаток и стоимость памяти

i = 0
пока i + 4 <= n:
    загрузить 4 элемента a и 4 элемента b
    сложить попарно; записать 4 элемента c
    i += 4
обработать оставшиеся n − i элементов без выхода за границы

При n = 10: два полных блока по 4 и остаток из 2 элементов. Остаток может обрабатываться скалярно или специальными загрузками и записями.

Разные strides: скалярные инструкции x86

Фрагмент кода Clang 17 для эквивалента общего цикла.
rdi, rsi, rdx — текущие адреса a, b, c;
r8 = 6, r9 = 22, rax = 2 — шаги в байтах.

LBB0_5:                        ; цикл остатка, r10 — счётчик
    movzx ecx, word ptr [rsi]   ; прочитать uint16 b[i]
    add   cx, word ptr [rdi]   ; сложить с a[i], 16 бит
    mov   word ptr [rdx], cx   ; сохранить uint16 c[i]
    add   rdi, r8              ; следующий a: +6 байт
    add   rsi, r9              ; следующий b: +22 байта
    add   rdx, rax             ; следующий c: +2 байта
    dec   r10
    jne   LBB0_5
Шаги приходят аргументами: умножать индекс на 3 и 11 в каждой итерации не требуется. Достаточно продвигать указатели.

Почему здесь не получилось SIMD

В NumPy 2.1.3 целочисленный add использует BINARY_LOOP_FAST. Для strides (6, 22, 2) выбирается общий цикл с тремя независимыми шагами.

У эквивалента, собранного Apple Clang 17 с -O3 -mavx2, основной цикл развёрнут по 4 элемента, но сложения остались скалярными. Развёртка цикла сама по себе не означает SIMD.

Чтобы сложить несколько пар векторно, нужно сначала собрать нужные uint16 в дорожки. Обычная загрузка подряд захватит и пропущенные элементы.

Неединичный stride не запрещает SIMD вообще. Но нужны подходящие загрузки и перестановки; выгода зависит от шагов, размера и реализации.

    def f(t):
        calls.append(float(t))
        return t + 1
    vf = np.vectorize(f, **options)
    vf([1., 1., 2.])
    print(len(calls))  # 4, затем 3, затем 3

По умолчанию: один пробный вызов для типа + три вызова по элементам. cache=True переиспользует ответ пробного вызова; otypes устраняет саму пробу.

Повторяющиеся единицы всё равно обрабатываются отдельно. Это не кэш ответов по значениям и не кэш JIT-компиляции.

Результат показан для вызова без signature. Дополнительная обёртка cache может добавить накладные расходы.

Strides и leading dimension

В классическом Fortran BLAS матрица хранится по столбцам.
Для float64: адрес A[i, j] = base + 8·(i + j·lda).

Как LAPACK использует BLAS уровня 3

В блочном LU-разложении после обработки панели обновляется оставшаяся подматрица:

[ A11  A12 ]   →   факторизовать панель и переставить строки
[ A21  A22 ]       вычислить блок U12 через TRSM
                  A22 ← A22 − L21 · U12 через GEMM

Панель содержит зависимости и выбор ведущего элемента. Обновление A22 — крупное матричное произведение с возможностями для кэша, SIMD и потоков.

LAPACK организует алгоритм, BLAS выполняет крупные операции. Время факторизации зависит и от панели, и от BLAS-ядер, и от размера блоков.

В эталонном DGETRF размер блока выбирает ILAENV; для подходящих размеров блочная ветвь вызывает DTRSM и DGEMM.

Один цикл вместо временных массивов

SSE прямой со слайда 37: n элементов float64. Модель обращений к массивам:

Возвести в квадратnn
Суммироватьn0

Параллелизм и fastmath

from numba import njit, prange

@njit(parallel=True)
def squared_error_parallel(p, x, y):
    total = np.float64(0)
    for i in prange(x.size):
        r = p[0]*x[i] + p[1] - y[i]
        total += r*r
    return total
Параллельная редукция меняет порядок сложения. fastmath — отдельное разрешение на дополнительные преобразования, а не обязательный переключатель скорости.

CuPy: знакомые массивы на GPU

import cupy as cp

# Те же p, x, y, без повторной генерации наблюдений.

def sse_cupy(p, x, y):
    r = p[0]*x + p[1] - y
    return cp.sum(r*r, dtype=cp.float64)

result = sse_cupy(pd, xd, yd)  # вычисление на GPU
back = cp.asnumpy(result)     # GPU → CPU

CuPy: замер с передачами

from timeit import repeat

def sse_roundtrip():
    pd, xd, yd = (cp.asarray(a) for a in (p, x, y))
    return cp.asnumpy(sse_cupy(pd, xd, yd))

answer = sse_roundtrip()  # прогрев контекста и ядер
r = p[0]*x + p[1] - y
assert np.isclose(answer, np.sum(r*r, dtype=np.float64),
                  rtol=1e-10, atol=1e-12)
cp.cuda.get_current_stream().synchronize()
times = repeat(sse_roundtrip, number=1, repeat=7)

Проверяем градиент SSE

Для rᵢ = kxᵢ + b − yᵢ:
∂SSE/∂k = 2Σrᵢxᵢ; ∂SSE/∂b = 2Σrᵢ.

# Базовый пример: p, x, y — float64.
r = p[0]*x + p[1] - y
analytic = 2*np.array([np.sum(r*x, dtype=np.float64),
                       np.sum(r, dtype=np.float64)])
assert np.allclose(np.asarray(g), analytic,
                   rtol=1e-10, atol=1e-12)
print("JAX:", np.asarray(g), "Формула:", analytic)
Проверяем обе компоненты, в том числе при ненулевой невязке. Для MSE градиент делится на n, для SSE/2 — на 2. Результат автодифференцирования проверяется так же, как любой численный результат.

JIT: компилируем всю цепочку

jit(sse_jax) передаёт компилятору цепочку:
k*x → +b → −y → квадрат → сумма.

  • Возможны fusion, устранение промежуточных массивов и сокращение запусков ядер.
  • Оптимизируется вся цепочка; out задаёт буферы отдельных операций.
  • Выигрыш зависит от backend, размера задачи, компиляции и передач.
from timeit import repeat
compiled_sse = jax.jit(sse_jax)
compiled_sse(pj, xj, yj).block_until_ready()  # прогрев
# Для замера ждём результат каждого вызова:
run = lambda: compiled_sse(pj, xj, yj).block_until_ready()
print(np.median(repeat(run, number=1, repeat=7)))
JAX работает и на CPU. Входы подготовлены до замера; первый вызов учитываем отдельно.

Точность и ограничения JAX

  • По умолчанию JAX ориентирован на 32-битные типы.
  • В примере явно включён режим x64 до создания массивов.

  • Обычное Python-ветвление по вычисляемому значению может не подходить трассировке.
  • Для сравнения с NumPy фиксируем dtype и допуски.
