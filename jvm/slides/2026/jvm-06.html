Что такое расширения

  • Добавление функций к классу без наследования
  • Синтаксис: fun Receiver.funcName() {}
  • this внутри — receiver
fun String.reverseWords(): String =
    this.split(" ").reversed().joinToString(" ")

"Hello World".reverseWords() // "World Hello"

Расширения позволяют добавлять новые функции к уже существующим классам, не изменяя их исходный код и не создавая подклассы. Это особенно полезно для классов из сторонних библиотек или стандартной библиотеки Java.

Невиртуальность — главное правило

  • Расширения разрешаются статически (по типу переменной)
  • НЕ по фактическому типу объекта
  • Это НЕ полиморфизм

В отличие от виртуальных методов, которые выбираются на основе фактического типа объекта во время выполнения, расширения выбираются компилятором на основе статического типа переменной. Это ключевое отличие, которое важно понимать при проектировании API.

Пример невиртуальности

open class Animal
class Dog : Animal()

fun Animal.speak() = "Animal"
fun Dog.speak() = "Dog"

fun printSound(a: Animal) {
    println(a.speak()) // "Animal" (не "Dog")!
}

printSound(Dog()) // Вывод: "Animal"

Внутри функции printSound параметр a имеет статический тип Animal. Компилятор видит расширение Animal.speak() и вызывает именно его, игнорируя тот факт, что фактический объект — Dog. Это поведение часто становится неожиданностью для разработчиков, привыкших к полиморфизму.

Конфликт с членом класса

class MyClass {
    fun print() = "Member"
}

fun MyClass.print() = "Extension"

MyClass().print() // "Member" (всегда выигрывает член)

Если в классе уже есть метод с такой же сигнатурой, как у расширения, приоритет всегда отдается члену класса. Расширение в этом случае просто игнорируется компилятором. Это защитный механизм, который предотвращает случайное переопределение существующего поведения.

Реализация под капотом

  • Компилятор превращает в статическую функцию
  • Первый аргумент — receiver
// Kotlin
fun String.reverseWords(): String

// Java (сгенерировано)
public static String reverseWords(String $this)

Когда вы объявляете расширение, компилятор Kotlin генерирует статическую функцию в байткоде. Первым параметром этой функции становится receiver — объект, для которого вызывается расширение. Именно поэтому расширения не могут быть виртуальными — статические функции не участвуют в динамической диспетчеризации.

Вызов из Java

// Файл: StringUtils.kt
package com.example
fun String.reverseWords(): String
// Java
String result = StringUtilsKt.reverseWords("Hello");

Из Java-кода расширения вызываются как обычные статические функции. Имя класса-обертки формируется из имени файла, в котором объявлено расширение, с добавлением суффикса Kt. Это важно учитывать при написании библиотек, которые будут использоваться из Java.

Аннотация @JvmName

@file:JvmName("StringExt")
package com.example
// Java
StringExt.reverseWords("Hello");

Аннотация @JvmName позволяет задать более осмысленное имя для класса-обертки, который генерируется для расширений. Это особенно полезно, когда у вас много расширений в одном файле, и вы хотите, чтобы из Java они выглядели как методы утилитного класса с понятным именем.

Расширения для примитивов

fun Int.isEven(): Boolean = this % 2 == 0
fun Int.squared(): Int = this * this

4.isEven() // true
5.squared() // 25

Kotlin позволяет расширять примитивные типы: Int, Long, Double, Boolean и другие. Это дает возможность добавлять доменные методы к числам, делая код более выразительным. Например, isEven() читается естественнее, чем number % 2 == 0.

Реализация для примитивов

  • Компилятор генерирует статическую функцию с примитивом (без боксинга)
// Java
public static boolean isEven(int $this) {
    return $this % 2 == 0;
}

Для примитивных типов компилятор генерирует статическую функцию, которая принимает примитив напрямую, без упаковки в объект-обертку. Это делает вызовы расширений для примитивов такими же эффективными, как и обычные вызовы методов.

Нюанс с ссылкой на функцию

list.map(Int::isEven) // Боксинг! Function1<Int, Boolean>

Когда вы передаете расширение как ссылку на функцию (например, в map), происходит упаковка примитива в объект. Это связано с тем, что функциональные типы в Kotlin работают с объектами. Если производительность критична, стоит избегать таких конструкций для примитивных типов.

Расширения для nullable-типов

fun String?.safeLength(): Int = this?.length ?: 0

val s: String? = null
s.safeLength() // 0

Расширения могут быть объявлены для nullable-типов. В этом случае внутри расширения нужно обрабатывать возможность null. Это удобно, когда вы хотите предоставить безопасные методы, которые не бросают исключений при работе с nullable-значениями.

Расширения для generic-типов

fun <T> List<T>.secondOrNull(): T? =
    if (size >= 2) this[1] else null

listOf(1,2,3).secondOrNull() // 2

Расширения могут быть объявлены для generic-типов. Это позволяет добавлять методы к целым семействам типов. Например, расширение List<T>.secondOrNull() работает для любого списка, независимо от типа элементов.

Extension properties

val String.isPalindrome: Boolean
    get() = this == this.reversed()

"radar".isPalindrome // true

Помимо функций, можно объявлять расширения-свойства. Они не могут иметь поле для хранения значения, но могут определять геттер и сеттер. Это удобно для вычисляемых свойств, которые зависят от receiver.

Companion object extensions

class MyClass {
    companion object { }
}

fun MyClass.Companion.create() = MyClass()

MyClass.create()

Можно расширять companion object класса. Это позволяет добавлять статические методы к классу, не изменяя его исходный код. Особенно полезно, когда вы не можете изменить класс, но хотите добавить фабричные методы или другие статические функции.

Расширения для вложенных классов

class Outer {
    class Inner {
        fun existing() = "Inner method"
    }
}

// Расширение для Inner
fun Outer.Inner.newExtension() = "Extension for Inner"

// Использование
val inner = Outer.Inner()
inner.newExtension() // "Extension for Inner"

Вложенные классы (nested classes) можно расширять так же, как и обычные. Синтаксис расширения использует полное имя вложенного класса: Outer.Inner. Это работает одинаково для статических вложенных классов.

Расширения для inner (внутренних) классов

class Outer {
    inner class Inner {
        fun existing() = "Inner method"
    }
}

// Расширение для Inner
fun Outer.Inner.newExtension() = "Extension for Inner"

// Использование
val outer = Outer()
val inner = outer.Inner()
inner.newExtension() // "Extension for Inner"

Внутренние классы (inner classes) также можно расширять. Синтаксис тот же — Outer.Inner. Разница лишь в создании экземпляра: для inner класса нужен экземпляр внешнего класса.

Разница между nested и inner

КритерийNested (static)Inner
СозданиеOuter.Inner()outer.Inner()
Доступ к OuterНетЧерез this@Outer
Расширениеfun Outer.Inner.f()fun Outer.Inner.f()

С точки зрения расширений, синтаксис одинаков для обоих типов вложенных классов. Разница проявляется только при создании экземпляров и доступе к внешнему классу.

Расширения для enum классов

enum class Color {
    RED, GREEN, BLUE
}

// Расширение для enum
fun Color.isWarm(): Boolean = this == Color.RED

// Добавление свойства
val Color.hexCode: String
    get() = when (this) {
        Color.RED -> "#FF0000"
        Color.GREEN -> "#00FF00"
        Color.BLUE -> "#0000FF"
    }

Color.RED.isWarm() // true
Color.BLUE.hexCode // "#0000FF"

Enum-классы можно расширять точно так же, как обычные. Это удобно, когда вы не можете изменить сам enum (например, он из сторонней библиотеки), но хотите добавить к нему доменные методы или вычисляемые свойства.

Enum — входные параметры в расширении

enum class Direction {
    NORTH, SOUTH, EAST, WEST
}

fun Direction.turn(degrees: Int): Direction {
    val index = (ordinal + degrees / 90) % entries.size
    return entries[index]
}

Direction.NORTH.turn(90) // EAST
Direction.NORTH.turn(270) // WEST

// Использование в when
fun Direction.isHorizontal(): Boolean = 
    this == Direction.EAST || this == Direction.WEST

Расширения для enum могут принимать параметры и использовать ordinal и entries для навигации по значениям. Это позволяет реализовывать методы, которые зависят от порядка объявления констант.

Расширения для интерфейсов

interface Repository {
    fun findById(id: Int): String?
}

// Расширение для интерфейса — работает для всех реализаций
fun Repository.findByIdOrThrow(id: Int): String {
    return findById(id) ?: throw NoSuchElementException("Not found: $id")
}

class UserRepository : Repository {
    override fun findById(id: Int): String? = if (id == 1) "John" else null
}

val repo = UserRepository()
repo.findByIdOrThrow(1) // "John"
repo.findByIdOrThrow(2) // Исключение

Расширения для интерфейсов работают для всех реализаций этого интерфейса. Это мощный инструмент: вы можете добавить новые методы к интерфейсу, не изменяя его и не ломая существующие реализации.

Интерфейс — расширение с дефолтной логикой

interface Logger {
    fun log(message: String)
}
// Расширение с реализацией по умолчанию
fun Logger.logError(message: String) {
    log("[ERROR] $message")
}
fun Logger.logInfo(message: String) {
    log("[INFO] $message")
}
class ConsoleLogger : Logger {
    override fun log(message: String) = println(message)
}
val logger = ConsoleLogger()
logger.logError("Something broke") // [ERROR] Something broke
logger.logInfo("All good") // [INFO] All good

Расширения интерфейсов часто используются для добавления вспомогательных методов, которые реализованы через существующие методы интерфейса. Это похоже на default-методы в Java, но с одним важным отличием: расширения не могут быть переопределены в реализациях.

Импорт расширений

// Файл: StringUtils.kt
package com.example.utils

fun String.reverse(): String = this.reversed()

// Файл: Main.kt
package com.example.app

import com.example.utils.reverse // Импортируем расширение

fun main() {
    "Hello".reverse() // "olleH"
}

Расширения нужно импортировать так же, как и обычные функции. Без импорта расширение не будет видно в другом файле. Это позволяет контролировать, какие расширения доступны в конкретном файле, и избегать случайных конфликтов.

Конфликты имен

// Файл: StringUtils1.kt
package com.example.utils1
fun String.reverse(): String = this.reversed()

// Файл: StringUtils2.kt
package com.example.utils2
fun String.reverse(): String = this.reversed().uppercase()

Если два разных пакета содержат расширения с одинаковой сигнатурой, возникает конфликт имен. Компилятор не позволит импортировать оба без явного разрешения. Это защита от неоднозначности.

Решение — import as

package com.example.app

import com.example.utils1.reverse as reverseSimple
import com.example.utils2.reverse as reverseUppercase

fun main() {
    "Hello".reverseSimple() // "olleH"
    "Hello".reverseUppercase() // "OLLEH"
}

Ключевое слово as позволяет переименовать импортируемое расширение. Это решает конфликты имен и делает код более читаемым, когда вы используете несколько версий одного и того же расширения из разных источников.

Приоритет разрешения

  1. Член класса — всегда выигрывает
  2. Расширение из того же файла/пакета
  3. Импортированное расширение
  4. Расширение из другого пакета (если импортировано)

Понимание приоритета разрешения важно для предсказуемости кода. Если вы объявили расширение в том же файле, где оно используется, оно будет иметь приоритет над импортированными. Член класса всегда побеждает любое расширение.

Арифметические операторы

ОператорФункция
+plus
-minus
*times
/div
%rem

Kotlin позволяет перегружать арифметические операторы через функции с ключевым словом operator. Каждый оператор соответствует определенной функции. Это работает как для членов класса, так и для расширений.

Пример: работа с деньгами

data class Money(val amount: BigDecimal, val currency: String)

operator fun Money.plus(other: Money): Money {
    require(currency == other.currency) { "Currency mismatch" }
    return Money(amount + other.amount, currency)
}

operator fun Money.times(factor: Double): Money =
    Money(amount * factor.toBigDecimal(), currency)

val salary = Money(1000.toBigDecimal(), "USD")
val bonus = Money(500.toBigDecimal(), "USD")
val total = salary + bonus // Money(1500, "USD")
val doubled = salary * 2.0 // Money(2000, "USD")

Перегрузка операторов позволяет сделать доменные операции естественными. Вместо salary.plus(bonus) можно писать salary + bonus. При этом оператор + проверяет соответствие валют и выбрасывает исключение при несоответствии — это логика, которая была бы неуклюжей в обычном методе.

Пример: работа с временем

data class Time(val hours: Int, val minutes: Int)
operator fun Time.plus(other: Time): Time {
    val totalMinutes = hours * 60 + minutes +
        other.hours * 60 + other.minutes
    return Time(totalMinutes / 60, totalMinutes % 60)
}
operator fun Time.times(factor: Int): Time {
    val totalMinutes = (hours * 60 + minutes) * factor
    return Time(totalMinutes / 60, totalMinutes % 60)
}
val workDay = Time(8, 30)
val break = Time(0, 45)
val fullDay = workDay + break // Time(9, 15)
val week = workDay * 5 // Time(42, 30)

Операторы + и * для времени делают код более выразительным. workDay + break читается как "рабочий день плюс перерыв", а workDay * 5 — как "рабочий день, умноженный на пять". Без перегрузки пришлось бы писать громоздкие вызовы методов.

Пример: повторение строк

operator fun Int.times(str: String) = str.repeat(this)

3 * "ab" // "ababab"

// DSL для генерации разделителей
fun separator(count: Int) = count * "-"
separator(10) // "----------"

Перегрузка оператора * для Int и String позволяет писать 3 * "ab" вместо "ab".repeat(3). Это особенно удобно в DSL для генерации повторяющихся строк, например, разделителей или отступов.

Операторы сравнения

ОператорФункция
> < >= <=compareTo
==equals (нельзя через extension)

Операторы сравнения >, <, >=, <= отображаются на функцию compareTo, которая возвращает Int: отрицательное число, ноль или положительное. Оператор == работает через equals и не может быть перегружен через расширение — только через член класса.

Пример: сравнение версий

data class Version(val major: Int, val minor: Int, val patch: Int = 0)

operator fun Version.compareTo(other: Version): Int {
    return compareValuesBy(this, other,
        { it.major },
        { it.minor },
        { it.patch })
}

val v1 = Version(2, 1, 0)
val v2 = Version(2, 2, 0)
v1 < v2 // true

val versions = listOf(v2, v1)
versions.sorted() // [Version(2,1,0), Version(2,2,0)]

Перегрузка compareTo позволяет использовать операторы сравнения для доменных типов. Это также дает возможность сортировать объекты с помощью стандартных функций, таких как sorted(), без дополнительных компараторов.

Операторы доступа позволяют использовать синтаксис индексации, проверки принадлежности, создания диапазонов и вызова объекта как функции. Это основа для создания выразительных DSL.

Пример: матрица

class Matrix(private val data: List<List<Int>>) {
    operator fun get(i: Int, j: Int): Int = data[i][j]
    operator fun set(i: Int, j: Int, value: Int) {
        // mutable implementation
    }
}

val m = Matrix(listOf(listOf(1,2), listOf(3,4)))
val value = m[0,1] // 2
m[0,1] = 10 // set

Перегрузка get и set позволяет использовать синтаксис индексации для многомерных структур. m[0,1] читается естественнее, чем m.get(0,1), особенно в математических вычислениях.

Пример: DSL для JSON

class JsonObject {
    private val map = mutableMapOf<String, Any>()
    
    operator fun get(key: String): Any? = map[key]
    operator fun set(key: String, value: Any) { map[key] = value }
    operator fun contains(key: String) = key in map
}

val json = JsonObject()
json["name"] = "John"
json["age"] = 30

val name = json["name"] // "John"
"age" in json // true

Операторы get, set и contains позволяют работать с объектом как с ассоциативным массивом. Это основа для построения DSL, где синтаксис json["key"] = value выглядит естественно и знакомо.

Invoke и дуализм объект/функция

Что такое invoke

  • Позволяет вызывать объект как функцию
  • obj() → obj.invoke()
  • Открывает тему дуализма: объект ↔ функция

Оператор invoke позволяет объекту быть вызванным как функция. Это стирает грань между объектом и функцией: объект может хранить состояние и при этом вызываться как функция. Это мощный инструмент для создания фабрик, замыканий с состоянием и DSL.

Callable object (объект с состоянием)

  • Объект, который ведет себя как функция
  • Сохраняет состояние между вызовами
  • Уместен, когда нужно сохранять контекст
class Counter(private val start: Int = 0) {
    private var count = start
    
    operator fun invoke(): Int = count++
}

val counter = Counter(10)
counter() // 10
counter() // 11
counter() // 12

Callable object — это объект с оператором invoke. Он может хранить состояние в полях и предоставлять дополнительные методы. Это полноценный объект, который ведет себя как функция.

Замыкание (функция с захваченным состоянием)

  • Функция, которая захватывает переменные из внешней области
  • Не имеет свойств, но хранит состояние через замыкание
  • Уместен, когда состояние локально и не требует инкапсуляции
fun createCounter(start: Int = 0): () -> Int {
    var count = start
    return { count++ }
}
val counter = createCounter(10)
counter() // 10
counter() // 11

Замыкание — это функция, которая захватывает переменные из окружающей области видимости. Оно не имеет полей и методов, но хранит состояние в захваченных переменных. Это легковесная альтернатива callable object.

Выбор между callable object и замыканием зависит от потребностей. Если нужны дополнительные методы, наследование или инкапсуляция — выбирайте callable object. Если состояние простое и локальное — замыкание будет легче и короче.

Примеры выбора

// 1. Нужны доп. методы → callable object
class Validator(private val rules: List<(String) -> Boolean>) {
    operator fun invoke(value: String): Boolean =
        rules.all { it(value) }
    
    fun addRule(rule: (String) -> Boolean) { ... }
    fun clearRules() { ... }
}

// 2. Простое состояние → замыкание
fun createValidator(rules: List<(String) -> Boolean>): (String) -> Boolean {
    return { value -> rules.all { it(value) } }
}

В первом случае нужны методы addRule и clearRules — это требует callable object. Во втором случае достаточно просто проверки — замыкание короче и не требует создания класса.

DSL с invoke и замыканиями

// Callable object для DSL
class RouteHandler(private val handler: (Request) -> Response) {
    operator fun invoke(request: Request): Response = handler(request)
    
    fun before(block: (Request) -> Unit) { ... }
    fun after(block: (Response) -> Unit) { ... }
}

// Замыкание для простых случаев
fun route(handler: (Request) -> Response): (Request) -> Response = handler

val getUsers = RouteHandler { req ->
    Response(200, "Users list")
}
getUsers.before { println("Logging request") }

val getHealth = route { req -> Response(200, "OK") }

В DSL выбор между callable object и замыканием зависит от сложности. Если нужны хуки before/after — нужен callable object. Если достаточно простой обработки — замыкание проще.

Причесывание легаси

Пример 1: java.util.Date

// Легаси: Date — куча deprecated методов
val date = Date()
date.year // deprecated
date.month // deprecated
date.date // deprecated

// Причесываем расширениями
fun Date.toLocalDate(): LocalDate =
    Instant.ofEpochMilli(this.time)
        .atZone(ZoneId.systemDefault())
        .toLocalDate()

fun Date.isWeekend(): Boolean {
    val day = this.toLocalDate().dayOfWeek
    return day == DayOfWeek.SATURDAY || day == DayOfWeek.SUNDAY
}

fun Date.plusDays(days: Long): Date =
    Date(this.time + days * 24 * 60 * 60 * 1000)

// Использование
val today = Date()
today.toLocalDate() // 2026-01-15
today.isWeekend() // false
today.plusDays(3) // Date + 3 дня

java.util.Date — классический пример легаси-класса с устаревшими методами. Расширения позволяют добавить современный API поверх старого класса, не изменяя его. Вместо deprecated-методов getYear(), getMonth() мы получаем чистые toLocalDate(), isWeekend(), plusDays().

Пример 2: java.io.File

// Легаси: File — громоздкий API
val file = File("/tmp/data.txt")
file.exists() // boolean
file.length() // long
file.listFiles() // File[]?

// Причесываем расширениями
fun File.readText(): String = this.readBytes().toString(Charsets.UTF_8)

fun File.writeText(text: String) {
    this.writeBytes(text.toByteArray(Charsets.UTF_8))
}

fun File.extension(): String =
    this.name.substringAfterLast('.', "")

fun File.isImage(): Boolean =
    extension() in setOf("jpg", "png", "gif", "bmp")

// Использование
val config = File("/etc/app/config.txt")
config.readText() // "server=localhost"
config.isImage() // false

java.io.File — громоздкий API, где даже простое чтение файла требует нескольких строк. Расширения добавляют современные методы readText(), writeText(), а также доменные проверки вроде isImage().

Пример 3: java.sql.ResultSet

// Легаси: ResultSet — индексы вместо имен
val rs = stmt.executeQuery("SELECT id, name FROM users")
rs.getInt(1) // магическое число
rs.getString(2) // магическое число

// Причесываем расширениями
fun ResultSet.getInt(name: String): Int = this.getInt(this.findColumn(name))
fun ResultSet.getString(name: String): String = this.getString(this.findColumn(name))

fun <T> ResultSet.map(transform: ResultSet.() -> T): List<T> {
    val result = mutableListOf<T>()
    while (this.next()) {
        result.add(transform())
    }
    return result
}

// Использование
val users = rs.map {
    User(
        id = getInt("id"),
        name = getString("name")
    )
}

java.sql.ResultSet — пример API, где приходится работать с магическими числами вместо имен колонок. Расширения добавляют перегрузки с именами, а метод map() позволяет функционально преобразовывать строки результата в объекты.

Пример 4: java.net.HttpURLConnection

// Легаси: HttpURLConnection — многословный
val conn = URL("https://api.example.com").openConnection() as HttpURLConnection
conn.requestMethod = "GET"
conn.connect()
val code = conn.responseCode
val body = conn.inputStream.bufferedReader().readText()
conn.disconnect()

// Причесываем расширениями
fun HttpURLConnection.getResponseBody(): String =
    this.inputStream.bufferedReader().use { it.readText() }

fun HttpURLConnection.setJsonBody(json: String) {
    this.doOutput = true
    this.setRequestProperty("Content-Type", "application/json")
    this.outputStream.use { it.write(json.toByteArray()) }
}

// Использование
val conn = URL("https://api.example.com").openConnection() as HttpURLConnection
conn.requestMethod = "POST"
conn.setJsonBody("""{"name": "John"}""")
val response = conn.getResponseBody()

HttpURLConnection — многословный API, где даже простой GET-запрос требует 5-6 строк. Расширения getResponseBody() и setJsonBody() скрывают детали работы с потоками и заголовками, делая код чище.

Итог: что дают расширения для легаси

  • Не меняя исходный код, добавляем современный API
  • Скрываем громоздкие конструкции
  • Даем типизацию там, где были магические числа
  • Улучшаем читаемость без риска сломать существующий код

Расширения — идеальный инструмент для работы с легаси-кодом. Вы не можете изменить старые классы, но можете добавить к ним современные методы, которые делают код чище и безопаснее. При этом существующий код продолжает работать без изменений.

Ограничения операторов

  • Нельзя создать новый оператор (только из фиксированного набора)
  • Нельзя изменить приоритет операторов
  • Нельзя перегрузить оператор, если он уже есть в классе (член класса выигрывает)

Kotlin предоставляет фиксированный набор операторов, которые можно перегружать. Вы не можете создать свой собственный оператор или изменить приоритет существующих. Также, если в классе уже есть метод с сигнатурой оператора, расширение не сможет его переопределить.

Анти-паттерны

  • Использовать расширения для полиморфизма — статическое разрешение ломает ожидания
  • Создавать расширения, конфликтующие с членами класса — член всегда выигрывает
  • Злоупотреблять операторами — страдает читаемость
  • Менять семантику операторов — плюс должен означать сложение, минус — вычитание

Расширения — мощный инструмент, но важно использовать их с умом. Не пытайтесь реализовать полиморфизм через расширения — для этого есть open-функции и интерфейсы. Не перегружайте операторы без необходимости — код должен оставаться читаемым и предсказуемым.

Практика

  1. operator fun Int.times(list: List<String>) — повторить список N раз
  2. operator fun String.div(n: Int) — разделить строку на N частей
  3. Реализуйте RetryHandler как callable object (счетчик попыток)
  4. Реализуйте тот же RetryHandler через замыкание
  5. Расширение для enum class Direction — метод isHorizontal()
  6. Расширение для interface List<T> — метод secondOrNull()
  7. Импортируйте два конфликтующих расширения с as
  8. Расширение для java.util.Random — метод nextIntRange(from, to)
  9. Расширение для java.util.Properties — метод getInt(key, default)
  10. Расширение для java.net.URL — метод readText()

Итоги

  • Статическое разрешение — главное ограничение
  • Из Java — через сгенерированный класс
  • Операторы позволяют строить DSL
  • Invoke — мост между объектом и функцией
