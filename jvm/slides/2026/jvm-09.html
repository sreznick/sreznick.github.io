Компиляция и выполнение

  • Компилятор Kotlin проверяет исходный код и создаёт JVM-байткод.

Class и выбор исследуемого типа

Java reflection

Публичные и объявленные члены

  • Java-метод getMethods(), доступный в Kotlin как methods, возвращает публичные методы, включая унаследованные.

Java reflection

Поиск метода и JVM-типы параметров

  • getMethod ищет публичный метод по имени и точным классам параметров, включая унаследованные методы.
  • Перегруженные методы различаются параметрами; для поиска одного имени недостаточно.

Java reflection

Рефлексивный вызов метода

  • Method.invoke принимает объект-получатель (receiver) и аргументы. Результат имеет тип Any?.
  • Для нестатического метода нужен объект подходящего класса. Для статического метода можно передать null.
  • При вызове проверяются аргументы, выполняются допустимые распаковка и расширение примитивов. Примитивный результат упаковывается; void даёт null.

val result = method.invoke(receiver, 2, 3) // 5

Java reflection

Три разных источника ошибок

  • При поиске: NoSuchMethodException означает, что метод с указанными параметрами не найден.
  • При вызове: IllegalAccessException сообщает о запрете доступа, IllegalArgumentException — о неверном получателе или аргументах.
  • Ошибка внутри целевого метода оборачивается в InvocationTargetException; исходное исключение доступно через cause.
val intType = Int::class.javaPrimitiveType!!
val divide = Calculator::class.java.getMethod(
    "divide", intType, intType)
divide.invoke(Calculator(), 1, 0)
// InvocationTargetException → ArithmeticException

MethodHandles

MethodHandle как значение

  • MethodHandle — типизированная исполняемая ссылка на метод, конструктор, доступ к полю или другую низкоуровневую операцию.
  • Её можно хранить, передавать, связывать с аргументами и адаптировать.
  • Method описывает объявление метода; MethodHandle представляет операцию с определёнными типами аргументов и результата.

MethodHandles

Lookup задаёт контекст доступа

  • MethodHandles.lookup() создаёт Lookup, связанный с классом вызывающего кода.
  • При поиске метода Lookup проверяет доступ от имени этого класса.
  • Готовый MethodHandle можно передать другому коду. При его вызове доступ не проверяется заново от имени нового вызывающего класса.

val handle = lookup.findVirtual(type, "add", signature)

MethodHandles

invokeExact и invoke

  • invokeExact требует точного совпадения типов аргументов и ожидаемого результата с типом MethodHandle.
  • invoke допускает адаптацию по правилам asType: например, некоторые преобразования примитивов и приведения ссылок.
  • Несовпадение сигнатур может привести к WrongMethodTypeException; приведение неподходящего объекта — к ClassCastException.

// as Int задаёт JVM-тип результата: int.
// Аргументы 2L и 3L не подходят для invokeExact.

InvocationHandler получает вызов как данные

  • InvocationHandler получает объект прокси, Method и массив аргументов. При отсутствии аргументов массив может быть null.

JDK Proxy

Делегирование и исключения

  • При делегировании через Method.invoke массив аргументов в Kotlin разворачивается оператором *.
  • Обработчик обычно распаковывает InvocationTargetException, чтобы передать клиенту исходную ошибку.
  • Checked-исключение, не разрешённое контрактом интерфейса, оборачивается в UndeclaredThrowableException.
try {
    method.invoke(target, *(args ?: emptyArray()))
} catch (error: InvocationTargetException) {
    throw error.targetException
}

JDK Proxy

JDK Proxy

Внутренний вызов при делегировании

  • Если прокси делегирует отдельному объекту target, внутри метода this указывает на target.

Открытость классов и методов в Kotlin

ClassLoader

Делегирование родителю

  • Стандартная реализация ClassLoader.loadClass сначала проверяет, загружен ли класс.
  • Затем делегирует запрос родителю. Если родителя нет, используется встроенный загрузчик JVM (bootstrap).
  • Если делегирование не нашло класс, вызывается findClass. Пользовательский загрузчик может изменить этот порядок.
child.loadClass(name)
  → findLoadedClass
  → parent.loadClass
  → findClass, если родитель не нашёл

Кто запросил класс и кто его определил

  • Идентичность класса зависит от определяющего загрузчика, а не только от того, через кого вызвали loadClass.

ClassLoader

Идентичность класса на JVM

  • Обычный класс определяется парой: бинарное имя и определяющий загрузчик.
  • Если два загрузчика независимо определили классы с одинаковым именем, это разные типы.
  • Экземпляр одного из этих классов нельзя привести к другому: такое приведение завершится ClassCastException.
("plugins.Service", loaderA)

Inline

Семантика inline

  • При прямом вызове inline-функции компилятор встраивает её тело в место вызова.
  • Лямбды для встраиваемых параметров раскрываются вместе с телом функции.
  • При этом у функции может сохраняться JVM-метод: inline не означает, что объявление полностью исчезнет из class-файла.

fun compute(seed: Int) = inlined { seed + 1 }
// Смысл места вызова после встраивания: seed + 1

  • Элементы не обходятся; их соответствие String не проверяется.
  • Поэтому список чисел может пройти проверку matches<List<String>>.
matches<List<String>>(listOf(1, 2)) // true

Ограничения типов

Почему ошибка возникает при чтении

  • Непроверяемое приведение к List<String> не проверяет типы элементов списка.
  • При чтении элемента как String сгенерированный код выполняет приведение самого элемента.
  • Если элемент оказался Integer, именно это приведение вызывает ClassCastException.
val value: Any = listOf(1, 2)
@Suppress("UNCHECKED_CAST")
val strings = value as List<String>
strings.first().length // ClassCastException

Ограничения типов

typeOf описывает запрошенный тип

  • В Kotlin выражение typeOf<T>() создаёт KType: описание аргументов типа и допустимости null.
  • Описания List<String> и List<Int> различаются.
  • Описывается тип из места вызова, а не тип, восстановленный из произвольного объекта.
typeOf<List<String>>() != typeOf<List<Int>>() // true
// Из этого не следует, что входной список проверен.

Ограничения типов

Описание типа и проверка содержимого

  • Class и KClass представляют классы; KType описывает тип с аргументами и допустимостью null.
  • Проверка is использует доступную во время выполнения информацию. Для проверки элементов нужен обход.
  • all проверяет текущее содержимое. Для пустого списка результат true, но исходный аргумент типа из этого не восстанавливается.
value is List<*> && value.all { it is String }
// Проверяет фактические элементы в момент обхода.

Основные различия

  • Свойство предоставляет доступ к значению; поле может хранить это значение.
  • Nullable разрешает null; значение по умолчанию разрешает пропуск обычного аргумента.
  • Идентичность класса зависит от имени и определяющего загрузчика.
  • Inline меняет код места вызова. Reified не проверяет содержимое коллекции.
