Что такое вложенные функции

Вложенные функции инкапсулируют логику, не загрязняя пространство имен.

Доступ к внешним переменным (часть 1)

fun calculateTotal(
    price: Double, 
    taxRate: Double
): Double {
    
    fun applyTax(amount: Double): Double {
        return amount * (1 + taxRate) // доступ к taxRate
    }
    
    fun applyDiscount(amount: Double): Double {
        return amount * 0.9 // фиксированная скидка
    }
    
    val withTax = applyTax(price)
    return applyDiscount(withTax)
}

calculateTotal(100.0, 0.2) // 108.0

Вложенные функции видят параметры внешней функции.

Доступ к внешним переменным (часть 2)

fun processOrder(
    items: List<Double>, 
    discount: Double
): Double {
    
    fun applyDiscount(amount: Double): Double {
        // Доступ к параметру discount
        return amount * (1 - discount)
    }
    
    fun formatPrice(amount: Double): Double {
        // Доступ к локальной переменной
        val precision = 2
        return Math.round(amount * 100.0) / 100.0
    }
    
    val subtotal = items.sum()
    val total = applyDiscount(subtotal)
    return formatPrice(total)
}

processOrder(listOf(10.0, 20.0, 30.0), 0.1) // 54.0

Замыкания

  • Определение
  • Захват переменных
  • Состояние между вызовами

Что такое замыкание (часть 1)

  • Функция, которая захватывает переменные
  • «Замкнута» на внешние переменные
  • Сохраняет доступ после выхода из внешней функции
fun createCounter(): () -> Int {
    var count = 0  // захваченная переменная
    return { count++ }
}

val counter = createCounter()
counter() // 0
counter() // 1
counter() // 2

Переменная count сохраняется в памяти.

Что такое замыкание (часть 2)

// Замыкание с параметром
fun createGreeter(prefix: String): (String) -> String {
    return { name -> "$prefix, $name!" }
}

val helloGreeter = createGreeter("Hello")
val hiGreeter = createGreeter("Hi")

helloGreeter("Alice") // "Hello, Alice!"
hiGreeter("Bob")      // "Hi, Bob!"

// Каждое замыкание хранит СВОЮ копию prefix
// helloGreeter и hiGreeter — независимы

Каждый вызов createGreeter создает новое замыкание.

Как работает захват

fun multiplier(factor: Int): (Int) -> Int {
    return { value -> value * factor }
}

val double = multiplier(2)
val triple = multiplier(3)

double(5) // 10
triple(5) // 15

Каждое замыкание захватывает свою копию переменных.

Замыкания и var vs val

// Захват var (изменяемая)
fun counter(): () -> Int {
    var count = 0
    return { count++ }
}

// Захват val (неизменяемая)
fun greetWith(prefix: String): (String) -> String {
    return { name -> "$prefix, $name!" }
}

val greet = greetWith("Hello")
greet("Alice") // "Hello, Alice!"

Замыкания могут захватывать var и val.

Практика: генератор ID

fun createIdGenerator(prefix: String): () -> String {
    var id = 0
    return { "${prefix}_${id++}" }
}

val userIdGen = createIdGenerator("user")
val orderIdGen = createIdGenerator("order")

userIdGen() // "user_0"
userIdGen() // "user_1"
orderIdGen() // "order_0"

Замыкания идеальны для генераторов уникальных значений.

Замыкания в коллекциях

val numbers = listOf(1, 2, 3, 4, 5)
var sum = 0
var count = 0

numbers.forEach { 
    sum += it
    count++
}

println("Sum: $sum, Count: $count") // Sum: 15, Count: 5

Лямбда в forEach захватывает sum и count.

Анонимные функции

  • Синтаксис
  • Отличия от лямбд
  • Применение

Что такое анонимная функция

  • Функция без имени
  • Объявляется с ключевым словом fun
  • Может иметь явный return
// Анонимная функция
val double = fun(x: Int): Int {
    return x * 2
}

// Лямбда (для сравнения)
val doubleLambda = { x: Int -> x * 2 }

double(5) // 10
doubleLambda(5) // 10

Анонимные функции похожи на лямбды, но имеют более гибкий синтаксис.

Синтаксис анонимной функции

// Полный синтаксис
val isEven = fun(x: Int): Boolean {
    return x % 2 == 0
}

// Сокращенный (expression body)
val isOdd = fun(x: Int): Boolean = x % 2 != 0

// Без указания типа возврата
val isPositive = fun(x: Int) = x > 0

Анонимные функции поддерживают все возможности обычных функций.

Отличия от лямбд (часть 1)

КритерийАнонимнаяЛямбда
Синтаксисfun(x: Int): Int { return x }{ x: Int -> x }
returnЯвныйНеявный
Тип возвратаМожно указатьВыводится
Параметры по умолч.ДаНет

Главное отличие — поведение return.

Отличия от лямбд (часть 2)

// Анонимная функция — return из функции
val process = fun(list: List<Int>): List<Int> {
    val result = mutableListOf<Int>()
    for (x in list) {
        if (x < 0) return result // выход из функции
        result.add(x * 2)
    }
    return result
}

// Лямбда — return из ВНЕШНЕЙ функции
fun processWithLambda(list: List<Int>): List<Int> {
    val result = mutableListOf<Int>()
    list.forEach { x ->
        if (x < 0) return emptyList() // return из processWithLambda!
        result.add(x * 2)
    }
    return result
}

В лямбде return выходит из внешней функции.

Использование с коллекциями

val numbers = listOf(1, 2, 3, 4, 5)

// Анонимная функция в filter
val evens = numbers.filter(fun(x: Int): Boolean {
    return x % 2 == 0
})

// Анонимная функция в map
val doubled = numbers.map(fun(x: Int): Int = x * 2)

println(evens) // [2, 4]
println(doubled) // [2, 4, 6, 8, 10]

Анонимные функции можно передавать в функции коллекций.

Анонимная функция с receiver

// Анонимная функция с receiver
val buildString = fun StringBuilder.(): String {
    append("Hello")
    append(" ")
    append("World")
    return toString()
}

val result = StringBuilder().buildString()
// "Hello World"

Резюме: анонимные функции

  • Функции без имени с ключевым словом fun
  • Поддерживают явный return
  • Могут иметь receiver
  • Альтернатива лямбдам для сложной логики

Лямбда-расширения

  • Определение
  • Receiver и this
  • Стандартные функции
  • Построение DSL

Что такое лямбда-расширение

  • Лямбда с receiver
  • Синтаксис: Тип.() -> Результат
  • Внутри лямбды this — receiver
// Лямбда-расширение для String
val printInfo: String.() -> Unit = {
    println(this) // this — строка
    println(length) // доступ к членам receiver
}

"Hello".printInfo() // Вызов

Внутри лямбды this ссылается на объект receiver.

Синтаксис и вызов (часть 1)

// Объявление
val buildMessage: StringBuilder.() -> Unit = {
    append("Hello")  // this.append("Hello")
    append(" ")
    append("World")
}

// Вызов через receiver
val sb = StringBuilder()
sb.buildMessage()
println(sb.toString()) // "Hello World"

this внутри — receiver (StringBuilder).

Синтаксис и вызов (часть 2)

// Через функцию, принимающую лямбду
fun createString(
    block: StringBuilder.() -> Unit
): String {
    val builder = StringBuilder()
    builder.block() // передаем receiver
    return builder.toString()
}

val result = createString {
    append("Kotlin")
    append(" rocks!")
}

println(result) // "Kotlin rocks!"

// Параметры в лямбда-расширении
val repeat: StringBuilder.(Int) -> Unit = { times ->
    repeat(times) { append("ab") }
}

Лямбда-расширения могут принимать параметры.

Receiver и this

data class Person(val name: String, val age: Int)

val describe: Person.() -> String = {
    // this — объект Person
    "$name is $age years old"
}

val alice = Person("Alice", 25)
alice.describe() // "Alice is 25 years old"

// Доступ к членам receiver без this
val isAdult: Person.() -> Boolean = { age >= 18 }
alice.isAdult() // true

Можно опускать this и обращаться к членам напрямую.

DSL на практике

  • Что такое DSL
  • Построение DSL с лямбда-расширениями

Что такое DSL

  • Domain-Specific Language — предметно-ориентированный язык
  • Позволяет описывать конфигурации естественным синтаксисом
  • Лямбда-расширения — основа DSL в Kotlin
// Пример DSL — конфигурация сервера
val server = configureServer {
    port = 8080
    host = "localhost"
    useTls = true
    maxConnections = 100
}

DSL позволяет писать код, который читается как естественный язык.

Построение DSL: базовый класс

class ServerConfig {
    var port: Int = 80
    var host: String = "localhost"
    var useTls: Boolean = false
    var maxConnections: Int = 50
    
    fun validate() {
        require(port in 1..65535) { "Invalid port" }
        require(host.isNotBlank()) { "Host required" }
    }
}

// Функция, принимающая лямбда-расширение
fun configureServer(block: ServerConfig.() -> Unit): ServerConfig {
    val config = ServerConfig()
    config.block()
    config.validate()
    return config
}

Для DSL нужны: класс с настройками, функция с лямбдой, валидация.

Использование DSL

val server = configureServer {
    port = 8080
    host = "api.example.com"
    useTls = true
    maxConnections = 200
}

// Без DSL пришлось бы писать:
val config = ServerConfig()
config.port = 8080
config.host = "api.example.com"
config.useTls = true
config.maxConnections = 200
config.validate()

DSL делает код чище и выразительнее.

Пример: HTML DSL (часть 1)

class HtmlBuilder {
    private val content = StringBuilder()
    
    fun head(block: HeadBuilder.() -> Unit) {
        val head = HeadBuilder()
        head.block()
        content.append(head.build())
    }
    
    fun body(block: BodyBuilder.() -> Unit) {
        val body = BodyBuilder()
        body.block()
        content.append(body.build())
    }
    
    fun build(): String = "<html>$content</html>"
}

Каждый тег — класс-билдер с методами для вложенных тегов.

Пример: HTML DSL (часть 2)

class HeadBuilder {
    private val content = StringBuilder()

HTTP-запрос DSL (часть 1)

class HttpRequestBuilder {
    var method: String = "GET"
    var url: String = ""
    val headers = mutableMapOf<String, String>()
    var body: String? = null
    
    fun header(key: String, value: String) {
        headers[key] = value
    }
    
    fun build(): HttpRequest {
        require(url.isNotBlank()) { "URL required" }
        return HttpRequest(method, url, headers, body)
    }
}

fun httpRequest(
    block: HttpRequestBuilder.() -> Unit
): HttpRequest {
    val builder = HttpRequestBuilder()
    builder.block()
    return builder.build()
}

builder.header("Authorization", "Bearer token123")
builder.body = """{"name": "Alice"}"""
val req = builder.build()

DSL делает код чище и выразительнее.

Преимущества DSL (часть 1)

  • Читаемость: код как естественный язык
  • Безопасность: компилятор проверяет структуру
  • Инкапсуляция: сложная логика скрыта
// Читаемость
val server = configureServer {
    port = 8080
    host = "api.example.com"
    useTls = true
}

// Безопасность — компилятор не даст:
// configureServer { port = "8080" } // Ошибка типа

Преимущества DSL (часть 2)

  • Переиспользование: DSL в разных местах
  • Валидация: проверки автоматически
  • Тестируемость: DSL легко тестировать
// Валидация в DSL
fun configureServer(
    block: ServerConfig.() -> Unit
): ServerConfig {
    val config = ServerConfig()
    config.block()
    
    // Автоматическая валидация
    require(config.port in 1..65535) { "Invalid port" }
    require(config.host.isNotBlank()) { "Host required" }
    
    return config
}

// Тестирование DSL
@Test
fun testServerConfig() {
    val config = configureServer {
        port = 8080
        host = "localhost"
    }
    assertEquals(8080, config.port)
}

Ограничения лямбда-расширений

  • Нельзя переопределить — только статическое разрешение
  • Нельзя использовать как член класса
  • Receiver доступен только внутри лямбды
  • Нельзя сохранить receiver для последующего использования

Лямбда-расширения — статические конструкции, разрешаются на этапе компиляции.

Анти-паттерны

  • Использовать DSL для простых операций — избыточно
  • Создавать слишком сложные DSL — трудно поддерживать
  • Игнорировать валидацию в DSL — риск ошибок
  • Смешивать DSL с бизнес-логикой — нарушение SRP

DSL — мощный инструмент, но его нужно использовать с умом.

Практика и итоги

Практические задания

  1. Создайте функцию buildString, принимающую лямбда-расширение StringBuilder.() -> Unit
  2. Реализуйте счетчик через замыкание
  3. Создайте анонимную функцию для фильтрации списка
  4. Напишите DSL для конфигурации базы данных (host, port, user, password)
  5. Используйте apply для инициализации объекта

Пример: buildString

fun buildString(block: StringBuilder.() -> Unit): String {
    val sb = StringBuilder()
    sb.block()
    return sb.toString()
}

val message = buildString {
    append("Hello")
    append(" ")
    append("World")
    append("!")
}

println(message) // "Hello World!"

Функция buildString — простейший пример лямбда-расширений.

Пример: счетчик через замыкание

fun createCounter(start: Int = 0): () -> Int {
    var count = start
    return {
        count++
    }
}

val counter = createCounter(10)
println(counter()) // 10
println(counter()) // 11
println(counter()) // 12

// Каждый счетчик независим
val counter2 = createCounter()
println(counter2()) // 0
println(counter2()) // 1

Замыкание позволяет создать счетчик с сохранением состояния.

Итоги занятия (часть 1)

  • Функции — объекты первого класса
  • Вложенные функции инкапсулируют логику
  • Замыкания сохраняют состояние
  • Анонимные функции — гибкая альтернатива
// Функция как объект
val sum = { a: Int, b: Int -> a + b }

// Вложенная функция
fun outer() {
    fun inner() = "nested"
}

// Замыкание
fun counter() = { var c = 0; c++ }

// Анонимная функция
val double = fun(x: Int) = x * 2

Итоги занятия (часть 2)

  • Лямбда-расширения — основа DSL
  • DSL делают код выразительным
