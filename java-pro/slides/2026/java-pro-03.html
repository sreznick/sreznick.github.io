Промышленная разработка на JVM. Лекция 3

  • java.nio

java.nio: обзор

  • Появился в Java 1.4 (2002) как альтернатива потоковой модели java.io — буферизованный, а не побайтовый доступ к данным
  • Buffer — контейнер данных с произвольным доступом (position/limit/capacity), а не однонаправленный поток байт
  • Channel — источник/приёмник данных (файл, сокет), работающий через буферы, с поддержкой произвольного доступа и эффективного копирования
  • Path/Files (NIO.2, Java 7) — современная замена java.io.File для работы с файловой системой
  • Неблокирующий многоканальный I/O (Selector) и асинхронные каналы

ByteBuffer: создание

val heapBuffer = ByteBuffer.allocate(1024)          // в куче JVM
val directBuffer = ByteBuffer.allocateDirect(1024)  // вне кучи

println(heapBuffer.capacity())  // 1024
  • capacity фиксируется при создании и не может быть изменена
  • allocate() — буфер поверх обычного byte[] в управляемой куче JVM, доступен напрямую через array()
  • allocateDirect() — память вне кучи JVM; дороже создать/освободить, меньше лишних копирований между JVM и нативными буферами ОС

Запись и чтение: put/get

val buf = ByteBuffer.allocate(16)
buf.put(1)
buf.put(2)
buf.put(3)

println(buf.position())
// 3 — сдвинулась после каждой записи

println(buf.limit())
// 16 — предел, пока равен capacity

buf.put(0, 99)
// абсолютная запись по индексу
println(buf.position())
// всё ещё 3 — position не сдвинулась

Запись и чтение: put/get

  • Относительные put()/get() каждый раз продвигают position на размер записанного/прочитанного значения
  • Абсолютные put(index, value)/get(index) обращаются по индексу напрямую и position не трогают
  • limit — граница, дальше которой ни читать, ни писать нельзя; по умолчанию равен capacity

flip / clear / rewind / compact

val buf = ByteBuffer.allocate(16)
buf.put(1); buf.put(2); buf.put(3)

buf.flip()             // limit = position (3), position = 0 — режим чтения
val first = buf.get()  // читаем 1, position -> 1

buf.rewind()           // position = 0, limit не меняется — перечитать с начала
buf.clear()            // position = 0, limit = capacity — готов к новой записи
buf.compact()          // сдвигает непрочитанные данные в начало, освобождая хвост под дозапись

flip / clear / rewind / compact

  • flip() — универсальный переход "закончил писать → хочу читать"; забыть его перед чтением — классическая ошибка новичков
  • clear() не стирает данные физически, а просто сбрасывает указатели — старые байты логически считаются неактуальными
  • compact() нужен, когда прочитали не всё: непрочитанный хвост переносится в начало буфера, чтобы можно было дописать данные, не потеряв его

Типизированные представления и порядок байт

val buf = ByteBuffer.allocate(4).order(ByteOrder.BIG_ENDIAN)
buf.putInt(65536)
buf.flip()
println(buf.getInt())  // 65536

val ints = intArrayOf(1, 2, 3)
val byteBuf = ByteBuffer.allocate(ints.size * Int.SIZE_BYTES)
byteBuf.asIntBuffer().put(ints)  // запись сразу нескольких int

Типизированные представления и порядок байт

  • order(ByteOrder.BIG_ENDIAN/LITTLE_ENDIAN) задаёт порядок байт при чтении/записи многобайтовых чисел — критично при обмене данными с другими системами
  • putInt()/getInt() и аналоги для других примитивов — удобные методы без ручной сборки байт побитовыми сдвигами
  • asIntBuffer()/asCharBuffer() — представление того же самого буфера как последовательности другого типа, без копирования данных

View-методы ByteBuffer

  • ByteBuffer предоставляет методы для создания view-буферов других типов:
    • asIntBuffer() — view как IntBuffer
    • asLongBuffer() — view как LongBuffer
    • asShortBuffer() — view как ShortBuffer
    • asCharBuffer() — view как CharBuffer
    • asDoubleBuffer() — view как DoubleBuffer
    • asFloatBuffer() — view как FloatBuffer
  • View-буферы разделяют общее состояние с исходным ByteBuffer:
    • Изменения в view видны в исходном буфере и наоборот
    • Позиция и лимит у view независимы от исходного буфера
    • Порядок байтов (ByteOrder) наследуется от ByteBuffer

Общее состояние view-буферов

  • View-буферы используют тот же массив данных, что и исходный ByteBuffer
  • Изменение данных через view отражается в исходном буфере
  • Позиция и лимит у view независимы — они не синхронизируются
  • Но данные общие — изменения видны обоим

Общее состояние: пример

  • Пример: 
    ByteBuffer byteBuffer = ByteBuffer.allocate(8);
byteBuffer.order(ByteOrder.BIG_ENDIAN);
// Записываем int через ByteBuffer
byteBuffer.putInt(0, 42);
// Создаем view
IntBuffer intView = byteBuffer.asIntBuffer();
// Читаем через view — видим 42
System.out.println(intView.get(0)); // 42
// Изменяем через view
intView.put(0, 100);
// Читаем через исходный буфер — видим 100
System.out.println(byteBuffer.getInt(0)); // 100

Чтение big-endian view: код

public class ViewReadExample {
    public static void main(String[] args) {
        ByteBuffer byteBuffer = ByteBuffer.allocate(8);
        byteBuffer.order(ByteOrder.BIG_ENDIAN);
        byteBuffer.putInt(0, 1);
        byteBuffer.putInt(4, 2);
        
        IntBuffer bigEndianView = byteBuffer.asIntBuffer();
        System.out.println("Big-endian view:");
        while (bigEndianView.hasRemaining()) {
            System.out.print(bigEndianView.get() + " ");
        }
    }
}

Идея Channel

  • Channel — это двунаправленный канал для передачи данных
  • В отличие от Stream (однонаправленный), Channel поддерживает и чтение, и запись
  • Основные реализации:
    • FileChannel — для работы с файлами
    • SocketChannel — для сетевых соединений
    • ServerSocketChannel — для серверных сокетов
    • DatagramChannel — для UDP
  • Channel работает с ByteBuffer, а не с байтовыми массивами

Channel vs Stream

  • Stream:
    • Однонаправленный (InputStream или OutputStream)
    • Работает с байтами и массивами байтов
    • Блокирующий ввод-вывод
    • Нет поддержки scatter/gather
  • Channel:
    • Двунаправленный (чтение и запись)
    • Работает с ByteBuffer
    • Поддержка неблокирующего режима
    • Поддержка scatter/gather (множественные буферы)
    • Прямой доступ к системным вызовам (mmap, sendfile)

Scatter/Gather: что это

  • Scatter (разбрасывание) — чтение данных из канала в несколько буферов: 
    ByteBuffer header = ByteBuffer.allocate(8);
ByteBuffer body = ByteBuffer.allocate(64);
ByteBuffer trailer = ByteBuffer.allocate(4);

ByteBuffer[] buffers = {header, body, trailer};

// Читаем из канала в несколько буферов
long bytesRead = channel.read(buffers);

Scatter/Gather: что это

  • Gather (сборка) — запись данных из нескольких буферов в канал: 
    // Записываем из нескольких буферов в канал
long bytesWritten = channel.write(buffers);

Scatter/Gather: мотивация

  • Снижение числа системных вызовов (один вызов вместо нескольких)
  • Естественное разделение данных на логические части (заголовок, тело, хвост)
  • Избегание копирования данных для объединения
  • Удобство работы с сетевыми протоколами, где сообщение состоит из нескольких частей

transferTo / transferFrom: идея

  • Методы FileChannel для прямой передачи данных между каналами
  • Работают на уровне ядра ОС (zero-copy) — без копирования в пользовательское пространство
  • transferTo() — передает данные из файла в другой канал
  • transferFrom() — принимает данные из другого канала в файл
  • Используют системные вызовы sendfile() или mmap()

Пример transferTo

  • Копирование файла через transferTo: 
    try (FileChannel source = FileChannel.open(Paths.get("input.bin"));
     FileChannel target = FileChannel.open(Paths.get("output.bin"),
             CREATE, WRITE)) {
    
    long position = 0;
    long size = source.size();
    
    // Передаем данные напрямую
    while (position < size) {
        position += source.transferTo(position, size - position, target);
    }
}

Пример transferTo

  • Аналогично работает transferFrom: 
    target.transferFrom(source, 0, source.size());
  • Zero-copy: данные не проходят через буферы Java

Path: основные возможности

  • Path — интерфейс для представления пути к файлу или директории
  • Создание: 
    Path p1 = Paths.get("/home/user/file.txt");
Path p2 = Paths.get("/home", "user", "file.txt");
Path p3 = Path.of("/home/user/file.txt");
  • Основные методы:
    • toString() — строковое представление
    • getFileName() — имя файла
    • getParent() — родительская директория
    • getRoot() — корень пути
    • resolve() — объединение путей
    • relativize() — относительный путь
    • normalize() — нормализация (убирает . и ..)

Files: основные операции

  • Files — утилитный класс для работы с файлами и директориями
  • Проверка и метаданные: 
    boolean exists = Files.exists(path);
boolean isDir = Files.isDirectory(path);
long size = Files.size(path);
FileTime lastModified = Files.getLastModifiedTime(path);

Files: основные операции

  • Создание и удаление: 
    Files.createFile(path);
Files.createDirectory(dir);
Files.createDirectories(nestedDir); // создает все родительские
Files.delete(path);
Files.deleteIfExists(path);
  • Копирование и перемещение: 
    Files.copy(source, target, StandardCopyOption.REPLACE_EXISTING);
Files.move(source, target, StandardCopyOption.ATOMIC_MOVE);

Files: чтение

  • Чтение всех байтов: 
    byte[] bytes = Files.readAllBytes(path);
  • Чтение всех строк: 
    List<String> lines = Files.readAllLines(path);
  • Чтение через BufferedReader: 
    try (BufferedReader reader = Files.newBufferedReader(path)) {
    String line;
    while ((line = reader.readLine()) != null) {
        System.out.println(line);
    }
}

Files: запись

  • Запись байтов: 
    Files.write(path, bytes);
  • Запись строк: 
    Files.write(path, lines);
  • Запись через BufferedWriter: 
    try (BufferedWriter writer = Files.newBufferedWriter(path)) {
    writer.write("Hello, world!");
}
  • Files работает с Path и автоматически управляет ресурсами

Files: walk по дереву

  • Обход дерева файлов: 
    // Рекурсивный обход всех файлов и директорий
try (Stream<Path> paths = Files.walk(Paths.get("/home/user"))) {
    paths.forEach(System.out::println);
}

// Обход с ограничением глубины
try (Stream<Path> paths = Files.walk(Paths.get("/home/user"), 2)) {
    paths.forEach(System.out::println);
}

Files: walk по дереву

  • Фильтрация по типу: 
    // Только файлы
try (Stream<Path> paths = Files.walk(Paths.get("/home/user"))) {
    paths.filter(Files::isRegularFile)
         .forEach(System.out::println);
}
// Только директории
try (Stream<Path> paths = Files.walk(Paths.get("/home/user"))) {
    paths.filter(Files::isDirectory)
         .forEach(System.out::println);
}

Files: walk по дереву

  • Поиск по расширению: 
    try (Stream<Path> paths = Files.walk(Paths.get("/home/user"))) {
    paths.filter(p -> p.toString().endsWith(".java"))
         .forEach(System.out::println);
}
  • walk возвращает Stream — ленивый обход, требует закрытия
  • Альтернатива: Files.list() для одного уровня, Files.find() с предикатом

Идея memory-mapped файлов

  • Файл отображается в адресное пространство процесса
  • Доступ к файлу через обычные операции с памятью
  • ОС сама синхронизирует память и диск
  • Данные читаются/пишутся без явных системных вызовов

Создание mapping

  • FileChannel.map() создает отображение: 
    FileChannel channel = FileChannel.open(path);
MappedByteBuffer buffer = channel.map(
    FileChannel.MapMode.READ_WRITE, 0, channel.size());
  • Режимы: READ_ONLY, READ_WRITE, PRIVATE

Чтение и запись

  • Через MappedByteBuffer как обычный буфер: 
    // Чтение
int value = buffer.getInt(0);

// Запись
buffer.putInt(0, 42);

// Изменения автоматически попадают в файл
  • Работает как ByteBuffer, но данные синхронизируются с файлом

Преимущества

  • Высокая производительность для больших файлов
  • Данные не копируются в пользовательское пространство
  • ОС управляет кэшированием и синхронизацией
  • Удобно для случайного доступа к данным
  • Позволяет работать с файлами больше RAM

Ограничения

  • Размер mapping ограничен адресным пространством (2 ГБ на 32-битных системах)
  • Не подходит для очень маленьких файлов (оверхед на создание)
  • Сложнее отлаживать ошибки синхронизации
  • Требует осторожности с многопоточным доступом

Пример: копирование файла

  • Копирование через memory-mapped: 
    try (FileChannel in = FileChannel.open(src);
     FileChannel out = FileChannel.open(dst, CREATE, WRITE)) {
    
    MappedByteBuffer mapped = in.map(READ_ONLY, 0, in.size());
    out.write(mapped);
}
  • Один вызов — и файл скопирован

Пример: случайный доступ

  • Чтение записей по индексу: 
    MappedByteBuffer buffer = channel.map(
    READ_WRITE, 0, channel.size());

// Читаем 1000-ю запись (каждая по 4 байта)
int offset = 1000 * 4;
int value = buffer.getInt(offset);

// Обновляем запись
buffer.putInt(offset, value + 1);
  • Идеально для баз данных и индексных структур

Когда использовать

  • Большие файлы (сотни МБ и больше)
  • Случайный доступ к данным
  • Частые чтения/записи в разные позиции
  • Совместный доступ между процессами (через общий файл)
  • Реализация баз данных, кэшей, индексных структур

Память вне кучи: идея

  • ByteBuffer.allocateDirect() выделяет память вне кучи JVM
  • Память управляется ОС, а не сборщиком мусора
  • Используется для:
    • Сетевых операций (NIO)
    • Работы с большими данными
    • Снижения нагрузки на GC

Выделение direct-буфера

  • Выделение: 
    // Выделяем 1 МБ вне кучи
ByteBuffer buffer = ByteBuffer.allocateDirect(1024 * 1024);

// Проверяем, direct ли буфер
boolean isDirect = buffer.isDirect(); // true
  • Отличие от обычного: 
    // Обычный буфер (в куче)
ByteBuffer heapBuffer = ByteBuffer.allocate(1024);
  • Direct-буферы быстрее для I/O, но дороже в выделении

Преимущества и ограничения

  • Преимущества:
    • Не создает давления на GC
    • Данные не перемещаются GC (стабильные адреса)
    • Быстрее для системных вызовов (нет копирования)
  • Ограничения:
    • Выделение медленнее (системный вызов malloc)
    • Требует ручного освобождения (или Cleaner)
    • Сложнее отлаживать утечки

Charset: основы

  • Charset — отображение символов в байты и обратно
  • Стандартные: UTF-8, UTF-16, ISO-8859-1, US-ASCII
  • Получение: 
    Charset utf8 = Charset.forName("UTF-8");
Charset utf8 = StandardCharsets.UTF_8;
  • Кодирование/декодирование: 
    byte[] bytes = "Hello".getBytes(StandardCharsets.UTF_8);
String text = new String(bytes, StandardCharsets.UTF_8);

Charset: кодирование и декодирование

  • Через CharsetEncoder/Decoder: 
    CharsetEncoder encoder = StandardCharsets.UTF_8.newEncoder();
ByteBuffer encoded = encoder.encode(CharBuffer.wrap("Hello"));

CharsetDecoder decoder = StandardCharsets.UTF_8.newDecoder();
CharBuffer decoded = decoder.decode(encoded);
  • Обработка ошибок: 
    decoder.onMalformedInput(CodingErrorAction.REPORT);
decoder.onUnmappableCharacter(CodingErrorAction.REPLACE);

Charset: работа с ByteBuffer

  • Декодирование из ByteBuffer: 
    ByteBuffer buffer = ByteBuffer.wrap(bytes);
CharBuffer chars = StandardCharsets.UTF_8.decode(buffer);
String text = chars.toString();
  • Кодирование в ByteBuffer: 
    CharBuffer chars = CharBuffer.wrap("Hello");
ByteBuffer encoded = StandardCharsets.UTF_8.encode(chars);
  • Удобно при работе с NIO и каналами

Charset: список доступных

  • Просмотр всех доступных: 
    SortedMap<String, Charset> charsets = Charset.availableCharsets();
charsets.forEach((name, cs) -> System.out.println(name));
  • Проверка поддержки: 
    boolean supported = Charset.isSupported("UTF-8");
  • Основные: UTF-8, UTF-16, UTF-16BE, UTF-16LE, ISO-8859-1, US-ASCII, windows-1251

Асинхронный I/O: мотивация

  • Проблема блокирующего I/O:
    • Поток ждет завершения операции и простаивает
    • Много потоков → много контекстных переключений
    • Ограничение по количеству потоков
  • Решение: не блокировать поток, а получить уведомление о завершении
  • Один поток может обслуживать тысячи соединений

Ключевые концепции

  • Selector — мониторинг нескольких каналов на готовность
  • SelectionKey — регистрация канала в селекторе с интересующими операциями
  • Non-blocking режим — операции не блокируют поток
  • CompletionHandler — обратный вызов при завершении операции
  • Future — асинхронный результат операции

Основные классы

  • AsynchronousChannelGroup — пул потоков для обработки
  • AsynchronousFileChannel — асинхронная работа с файлами
  • AsynchronousSocketChannel — асинхронные сокеты
  • AsynchronousServerSocketChannel — асинхронный сервер
  • CompletionHandler<V, A> — интерфейс с completed() и failed()

Пример: асинхронное чтение

AsynchronousFileChannel channel = AsynchronousFileChannel.open(path);

ByteBuffer buffer = ByteBuffer.allocate(1024);
channel.read(buffer, 0, buffer, new CompletionHandler<Integer, ByteBuffer>() {
    @Override
    public void completed(Integer result, ByteBuffer attachment) {
        attachment.flip();
        System.out.println("Прочитано: " + result + " байт");
    }

    @Override
    public void failed(Throwable exc, ByteBuffer attachment) {
        System.err.println("Ошибка: " + exc);
    }
});

Пример: Selector

    Selector selector = Selector.open();
SocketChannel channel = SocketChannel.open();
channel.configureBlocking(false);
channel.register(selector, SelectionKey.OP_READ);
// Обработка событий
while (true) {
    selector.select(); // ждем событий
    
    for (SelectionKey key : selector.selectedKeys()) {
        if (key.isReadable()) {
            // читаем из канала
        }
    }
}

Преимущества и ограничения

  • Преимущества:
    • Масштабируемость (тысячи соединений на поток)
    • Эффективное использование ресурсов
    • Подходит для высоконагруженных серверов
  • Ограничения:
    • Сложность разработки и отладки
    • Труднее читать последовательный код
    • Требует аккуратности с общими данными
